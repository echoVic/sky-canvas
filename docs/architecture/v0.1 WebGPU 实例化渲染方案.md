# v0.1 WebGPU 实例化渲染方案

> 目标里程碑:WebGPU 原生渲染 **10 万+ 2D 对象**,pan/zoom 保持 **60fps**,较 Canvas2D 快一个量级。这是引擎收敛到「WebGPU 无限画布」主线后的第一个可量化交付。

## 背景与问题

当前 `packages/render-engine` 的 WebGPU 绘制链路(`adapters/webgpu/WebGPURenderer.ts`)已能正确渲染单个矩形 / 圆 / 线,地基质量良好:

- 设备 / 上下文 / 管线缓存 / buffer 管理 / WGSL shader 均为真实实现,零桩(`WebGPUPipelineManager`、`WebGPUBufferManager`、`WebGPUShaders`)。
- 坐标系统(`math/CoordinateSystem`)、四叉树剔除(`culling/SpatialPartitioning`)主线内核 typecheck 全绿。

**但存在一个对「海量对象」目标致命的瓶颈**:现有 `WebGPURenderer.drawGeometry()`(即时模式)每绘制一个图形都会:

1. 新建 vertex buffer + index buffer;
2. 一次 `drawIndexed`(1 个 draw call);
3. 立即 `destroy()` 两个 buffer。

绘制 10 万对象 = 10 万次 buffer 创建/销毁 + 10 万 draw call,会慢到不可用,**无法达成 v0.1 目标**。

现有 `batch/InstancedStrategy` 是为 **WebGL** 写的(依赖 `gl.getExtension('ANGLE_instanced_arrays')`、`drawElements`),**不能用于 WebGPU**;WGSL shader 目前也无 per-instance 输入。

**结论**:v0.1 的核心攻坚点不是「从零写 WebGPU 渲染」(该部分健康),而是**新增一条 WebGPU 实例化渲染路径**——这恰是本引擎相对 tldraw / excalidraw(Canvas2D)、PixiJS(WebGL)的护城河。

## 方案设计

一次 `drawIndexed(indexCount, instanceCount)` 渲染所有同类矩形:共享一个单位 quad 的 vertex/index buffer,per-instance 数据(位置、尺寸、颜色)放独立的 instance buffer。

### 1. 新增 WGSL 实例化 shader（`WebGPUShaders.ts`）

在现有 `BASIC_2D_VERTEX_SHADER` 旁新增 `INSTANCED_RECT_VERTEX_SHADER`,复用现有 `Uniforms { projectionMatrix, modelMatrix }` 约定:

```wgsl
struct Uniforms { projectionMatrix: mat3x3<f32>, modelMatrix: mat3x3<f32> }
struct VertexInput {
  @location(0) position: vec2<f32>,      // 单位 quad 顶点 (0,0)~(1,1)
  @location(1) i_offset: vec2<f32>,      // per-instance: 世界坐标位置
  @location(2) i_size: vec2<f32>,        // per-instance: 宽高
  @location(3) i_color: vec4<f32>,       // per-instance: 颜色
}
// 顶点 = i_offset + position * i_size,再过 model/projection
```

片段着色器复用现有 `BASIC_FRAGMENT_SHADER`。

### 2. 扩展管线支持双 vertex buffer + instance step-mode

`WebGPUPipelineManager` 当前 `getPipeline` 只接受单个 buffer 且 `createVertexBufferLayout` 硬编码 `stepMode: 'vertex'`(见 `WebGPUPipelineManager.ts:165, 241`)。需要:

- `createVertexBufferLayout` 支持传入 `stepMode`('vertex' | 'instance');
- `getPipeline` 的 `vertex.buffers` 支持数组(quad layout + instance layout 两个);
- 新增 `ShaderType.INSTANCED_RECT` 枚举与 `getInstancedRectPipeline()`;
- 在 `WebGPUBufferManager.VERTEX_LAYOUTS` 加 `INSTANCE_RECT` 布局(i_offset/i_size/i_color)。

### 3. 绘制器新增实例化入口（`adapters/webgpu/WebGPURenderer.ts`）

新增 `drawInstancedRects(instances: RectInstance[])`：

- 单位 quad 的 vertex/index buffer **只建一次并缓存**(不再逐帧建/毁);
- 把所有实例打包成一个 `Float32Array`(每实例 8 float:offset.xy + size.xy + color.rgba),写入 instance buffer;
- `setPipeline(instancedPipeline)` → `setVertexBuffer(0, quad)` → `setVertexBuffer(1, instanceBuffer)` → `setIndexBuffer` → `drawIndexed(6, instances.length)`;
- `stats.drawCalls += 1`(而非 += instanceCount)。

### 4. 接入无限画布视口 + 四叉树剔除

- 复用 `math/CoordinateSystem` 的 world↔screen 矩阵,填 `Uniforms.projectionMatrix`;
- pan/zoom 更新 viewport → 更新 projection uniform;
- 复用 `culling/SpatialPartitioning` 四叉树:每帧只 query 视口内实例,打进 instance buffer(剔除发生在 CPU 侧、上传前)。

## 复用清单(不重写)

| 复用 | 路径 |
|---|---|
| 设备/上下文初始化 | `adapters/webgpu/WebGPUContextImpl.ts` |
| 管线缓存框架 | `adapters/webgpu/WebGPUPipelineManager.ts`(扩展,非重写) |
| buffer 管理 | `adapters/webgpu/WebGPUBufferManager.ts` |
| WGSL 现有 shader/Uniforms 约定 | `adapters/webgpu/WebGPUShaders.ts` |
| 坐标系/矩阵 | `math/CoordinateSystem.ts`、`math/Matrix*` |
| 四叉树剔除 | `culling/SpatialPartitioning.ts` |
| 帧生命周期 | `WebGPURenderer.beginFrame/endFrame`(已实现) |

## 新增文件(预估)

- `adapters/webgpu/WebGPUShaders.ts` 内新增 instanced shader 常量(改现有文件)
- `adapters/webgpu/WebGPURenderer.ts` 内新增 `drawInstancedRects`(改现有文件)
- `examples/perf-demo/`:v0.1 性能 demo 页(WebGPU 渲 N 个矩形 + pan/zoom + FPS HUD + 对象数/draw call 数)

## 验收标准

1. Demo 页在支持 WebGPU 的浏览器渲染 **≥10 万矩形**,pan/zoom 稳定 **60fps**;
2. draw call 数 = **O(1)**(每种图元一次),而非 O(N);
3. 同场景 Canvas2D 基线明显卡顿,产出一张 FPS 对比图;
4. `pnpm --filter @sky-canvas/render-engine` typecheck 主线保持零错误。

## 明确不做（推后到 v0.2+）

- 文本渲染(SDF/图集)、图片/纹理绘制(现为桩,v0.1 排除)
- 路径/贝塞尔填充、裁剪、动画、hit-test
- WebGL / Canvas2D 后端(已移出主线)

## 风险

- **无 GPU 环境**:当前开发环境无 GPU,WebGPU 运行时无法验证,只能保证代码 + 类型正确,实际渲染与 FPS 需在本地带 GPU 的浏览器验证。
- **instance buffer 上限**:10 万实例 × 8 float × 4 byte ≈ 3.2MB,单 buffer 可承载;若后续要百万级需分批或改用 storage buffer。
